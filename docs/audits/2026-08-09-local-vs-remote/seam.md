# The seam: where `Handle` and `Client` diverge, and why

Repo `/Users/pedrocunha/repos/keylink`, `main` at `0119504`. Read-only pass.

All line references are to the file named. Macro line numbers point at the
**generating arm**, not at expanded code.

---

## 0. What the seam actually has on each side

One `service!` block generates **five** caller-side surfaces, not two.

| Surface | Type | Built by | Where |
|---|---|---|---|
| Local | `Handle<A>` | `actor`, `actor_with`, `actor_wired`, `actor_deep`, `supervised`, `supervised_deep` | `macros.rs:1970`, constructors `1602`-`1799` |
| Remote, unkeyed | `Client` | `Client::connect` | `macros.rs:2609`, `2628` |
| Remote, unkeyed, keyed ledger | `IdempotentClient` | `Client::with_idempotency` | `macros.rs:2719`, `2653` |
| Remote, keyed | `KeyedClient` + `ActorRef<'a>` | `KeyedClient::connect` then `at` | `macros.rs:2412`, `2550`, `2572` |
| Remote, blocking | `Client` (blocking module) | `connect` | `macros.rs:2783` |

The serving side is one trait, `Actor`, generated by `__keylink_actor_method!`
(`macros.rs:3613`). It is shared. A handler cannot tell which caller reached it
except through `Caller<'_>` (`middleware.rs:389`).

**The crate's stated position, quoted.** RFC-04 §5.5, `docs/rfc-04-actors.md:783`:

> ### 5.5 This rejection of location transparency is permanent
>
> Recorded here so that a future proposal to unify `Handle` and `Client` has an answer
> already written, rather than relitigating section 5.2 from scratch.
>
> **`MailboxClosed` and `keylink::Error` stay distinct, and the two types stay distinct.**
> The reason is not taste. A unified handle must either claim failures the local case cannot
> have, or hide failures the remote case does have. `keylink::Error::Transport`,
> `Error::Closed`, `Error::SchemaMismatch` and `Error::Remote` have no local counterpart —
> none of them, not one. A local mailbox has exactly one failure: the task is gone.
>
> Merging them would make keylink the first place in this crate where a caller cannot tell
> from the type what can go wrong. That is the opposite of the property `error.rs` is built
> around, and it is the property section 5.2 says the crate should not trade away.
>
> If a future RFC proposes the unification, it must first answer what
> `Error::SchemaMismatch` means for two objects in one process. There is no honest answer,
> which is the point.

The generated `Handle` carries the same argument in short form, at
`macros.rs:1835-1839`.

Take `rpc Ping(n: u64) -> u64;` in `service Expansion` (the crate's own
expansion, `macros.rs:4053`).

`Result<T>` with one parameter is `keylink::Result<T>`, that is
`Result<T, Error>` (`error.rs:318`).

### 1.2 What does NOT differ, and it is worth stating

- **Receiver.** Every caller-side method takes `&self`. Both sides. `&mut self`
  appears only on the serving trait (`3651`). The local/remote axis is not the
  `&self`/`&mut self` axis.
- **Argument names, order and types.** Identical on all four caller surfaces.
  No local method takes a reference where a remote one takes a value.
- **Ownership.** Both sides take the arguments by value. A local call **moves**
  them into a `Mail` variant (`3854-3859`) and does not borrow. So a local
  caller pays the move a remote caller pays, minus the encode.
- **Asyncness.** Every method is `async` except on the blocking client
  (`3084`, `3091`), which is a runtime concern rather than a location concern.
- **Kind selection.** Both sides read the same declared kind. Neither side
  renames a method.

### 1.3 What differs, per method

1. **Error type.** `Undelivered` or `NotQueued` locally, `Error` remotely. See
   §4.
2. **`tell` return.** Both sides drop the declared return type and answer `()`.
   The local doc says why at `3868-3872`. The remote doc says why at
   `3981-3985`. The two reasons are the same sentence.
3. **`tell` ordering.** Local `tell` is FIFO for two awaits on one task
   (`3874-3879`). Remote `tell` is not ordered: each call takes its own QUIC
   stream (`2561-2570`).
4. **`blob` return.** `BlobId` locally, `BlobHandle` remotely. The local doc
   states the physical fact at `3911-3915`: *"a handle is an address plus the
   node that holds it, and in this process the holder is you. No grant is
   recorded either, because a grant is permission for a *peer* and there is no
   peer here."*
5. **Body kinds.** `send` and `recv` have no local method at all. §2 covers it.
6. **Argument bounds.** A local argument must satisfy the mailbox: `Mail` is
   `Send + 'static`. A remote argument must satisfy `Serialize`,
   `Deserialize` and `postcard_schema::Schema`, because it enters the hashed
   contract (`reply.rs:222`, `reply.rs:244`).

## 3. Class defences, for the contested ones

**L2 is two claims and they split.** That a panic unwinds in the caller's own
thread is physics: an unwind is a stack operation and does not cross a process.
That a local caller has **no value form** of the fault is a decision. The
mechanism exists — `LocalActor::ask_catching` answers `TurnLost::Faulted(panic)`
(`turns.rs:3941`) — and the generated `Handle` does not expose it. The stated
reason is completeness of `Undelivered`: `macros.rs:3842-3845` says *"a fault is
the one loss missing, and it is missing because this method resumes the panic in
the caller rather than reporting it"*.

**L5, L6, L7 are INCIDENTAL and the crate says so indirectly.** Nothing physical
stops a peer asking for liveness or queue depth. `System::status`
(`actor/registry.rs:1768`) already computes the answer for keyed actors on the
serving side. The cost of closing them is one `WireRequest` arm, which moves
every service's ALPN — `reply.rs:48-53` records exactly that consequence for a
variant removal.

**R11 is INCIDENTAL, not essential, and the code says it in one line.**
`Undelivered::Expired` is a public variant that no local caller can produce.
`turns.rs:3265-3267`: *"Unreachable from a local call today ... this path builds
its own local `Origin`, one carries no `Queueing`, and there is nothing to
expire."* The variant was kept rather than folded, on the argument at
`3268-3271`. So the type already admits the parity that the doors do not.

**R9 is ESSENTIAL as built, and the boundary is precise.** `Middleware` wraps a
`Dispatch` (`rpc.rs:1390`). `Handle::service` builds a `Dispatch`
(`macros.rs:2147`). A local method never builds one — `__keylink_local_method!`
calls `self.inner.ask(..)` and reaches the mailbox directly
(`macros.rs:3853-3860`). So a layer is a property of *being served*, not of
being remote. A served actor's local `Handle` also bypasses every layer while
peers pass through them, on one mailbox (`macros.rs:2035-2036`).

**L11 and R3 are DELIBERATE and their arguments are on record.** For the mailbox
depth, RFC-04 §6.2 (`docs/rfc-04-actors.md:826`) fixes capacity 1 and says
*"There is no drop policy, no overflow error, no dead-letter queue, and nothing
to configure."* For idempotency, `macros.rs:2028-2033` records that the ledger
was never the missing half — the missing half was a generated client able to
attach a key, and `KeyedClient::with_idempotency` is it.

**R16 is the clearest DELIBERATE refusal in the file.** `macros.rs:3705-3716`:

> It stays absent for a reason of its own. A keyed message can be refused
> for four things a singleton `tell` cannot: a malformed id, an id nothing
> is mounted under, a registry at its capacity, and a queue budget that
> expired before a permit arrived. All four are decided AFTER the bytes
> reach the wire, and all four are reported on the reply — so a keyed `tell`
> would be fire-and-forget into a registry that can refuse four ways the
> caller can never learn about, including "you addressed an actor that does
> not exist", which is the mistake a caller most wants to hear about.
>
> A caller who wants fire-and-forget to a keyed actor writes an `rpc`
> returning `()` and drops the result, which is honest about the round trip
> it pays for. Absent and documented, rather than present and lying.

The same comment records that the **old** reason is dead: drift is refused at the
handshake now, and `RpcClient::tell` plus `serve_one_tell` would work.

**RFC-06 §6 is the second known refusal site, and half of it is overturned.**
`docs/rfc-06-observers.md:605` is headed *"PARTIALLY SUPERSEDED, 2026-08-07"*.
The rule that survives is the one that shapes the remote error surface:

> ~~No new `RemoteError` variant, because that moves the wire contract.~~ **The rule survives;
> the reason it was listed does not.** Wave 9 needed to tell a peer that an actor is restarting
> rather than gone, and did it *without* a new variant — a `"restarting: "` prefix inside
> `Failed`, matching Wave 1b's `"panicked: "` discipline.

That rule is why the remote side reports five conditions as prefixed strings
instead of five variants. See §4.

**RFC-07 §9.8 refuses supervision features, not seam features.**
`docs/rfc-07-the-turn-model.md:2835` lists `Supervisor`, `Strategy`,
`OneForAll`/`RestForOne`, parent/child trees, `Watching`, a fault-injection seam
and an incarnation counter. It states *"`LocalActor::incarnations()` does not
exist, was confirmed absent repo-wide, and none was added."* This is a
local-side refusal. It widens the L-column gap indirectly: a local caller cannot
count incarnations either, so neither side can.

## 4. The error surfaces, side by side

### 4.1 The shapes

| | Local | Remote |
|---|---|---|
| Value doors | `Undelivered`, 7 variants, **exhaustive** | `Error`, 17 variants, `#[non_exhaustive]` |
| Queue doors | `NotQueued`, 2 variants, **exhaustive** | — |
| Serving-side refusal | — | `RemoteError`, 5 variants, `#[non_exhaustive]` |
| Discriminators inside one variant | — | 5 `Failed` prefixes |

`Undelivered` at `turns.rs:3167`. `NotQueued` at `turns.rs:3353`. `Error` at
`error.rs:17`. `RemoteError` at `reply.rs:58`. The five prefixes at
`reply.rs:154`, `161`, `181`, `189`, `206`.

### 4.2 One condition, both sides

The translation happens in three functions: `deliver_to_local`
(`turns.rs:4680`), `rendered` (`turns.rs:4538`) and `lost` (`turns.rs:4616`).

| Condition | Local caller gets | Peer gets | Evidence |
|---|---|---|---|
| Handler returned | `Ok(T)` | `Ok(T)` | `3851`; `4543` |
| Handler panicked | **the panic, resumed** | `Error::Remote(Failed("panicked: {msg}"))` | `turns.rs:3905`; `turns.rs:4547` |
| Observer refused the turn | `Undelivered::Refused { name }` | `Failed("observer refused: {name}")` | `turns.rs:3230`; `4554` |
| Observer panicked | `Undelivered::ObserverPanicked { name }` | `Failed("observer panicked: {name}")` | `turns.rs:3258`; `4562` |
| Live actor dropped the reply | `Undelivered::Dropped` | `Failed("dropped: the actor is serving and this reply was never answered")` | `turns.rs:3203`; `4639` |
| Incarnation died, restart coming | `Undelivered::Restarting` (fact only) | `Failed("restarting: {reason}")` (fact **and** reason) | `turns.rs:3215`; `4618` |
| Actor gone | `Undelivered::Gone` | `RemoteError::NoSuchActor { id }` | `turns.rs:3192`; `4644`, `4732` |

| Queue budget expired | `Undelivered::Expired` (**unreachable**) | `RemoteError::TimedOut { millis }` | `turns.rs:3273`, `3265`; `4568`, `4719` |
| Re-entrant call | `Undelivered::Reentrant` / `NotQueued::Reentrant` | `Failed(<the local Display text>)`, **no prefix**, **unreachable** | `turns.rs:3288`, `3409`; `4773-4778` |

The `id` in `NoSuchActor` is the service name on the singleton path and the
actor id on the keyed path (`turns.rs:4614-4615`, `4733`).

### 4.3 Reportable on one side only

**Remote only — no local counterpart exists.** `Error::Transport`,
`Error::Codec`, `Error::FrameTooLarge`, `Error::FrameTruncated`,
`Error::Closed`, `Error::SchemaMismatch`, `Error::NotAByteStream`,
`Error::BodyTruncated`, `Error::BodyOverrun`, `Error::BodyTooLarge`,
`Error::UnexpectedResponse`, `Error::BlobRefused`, `Error::HandlerPanic`,
`Error::BlockingInAsync`, `Error::Config`, `Error::Io` (`error.rs:17-178`);
plus `RemoteError::Unauthorized`, `RemoteError::TimedOut`,
`RemoteError::Idempotency` (`reply.rs:61`, `65`, `75`). RFC-04 §5.5 names four
of these as the whole argument.

**Local only — a peer cannot learn it.**

1. **A fault as a value.** Not reachable through the generated `Handle` either.
   Locally the panic is raised; remotely it is a prefixed string. Neither side
   gets a typed fault.
2. **The observer's own error.** `Ended::Observer { name, error, fatal }`
   carries the error behind an `Arc` (`observe.rs:470`). A peer gets the
   name inside a prefix and nothing else. `reply.rs:177-180` states this.
3. **The ending itself.** `Ended` has six variants — `Stopped` (`455`),
   `Vanished` (`458`), `Panicked` (`465`), `Observer` (`470`), `Feed` (`502`),
   `GaveUp` (`522`), all in `observe.rs`. A peer sees one `NoSuchActor` for all
   six.
4. **The restart reason.** `Undelivered::Restarting` is a **unit** variant, and
   the reason is dropped at `turns.rs:3913`. The peer's
   `"restarting: {reason}"` carries it. Here the **peer is better informed than
   the local caller**, and the cause is stated at `turns.rs:3207-3213`:
   `Undelivered` is `Copy` and `Eq`, and an `Arc` is neither.
5. **Queue depth, busy-ness, liveness.** L5-L7 above.

### 4.4 The condition neither side reports the same way twice

`Undelivered::Gone`, `NotQueued::Closed` and `TurnLost::Gone` carry **one
sentence** — *the actor is no longer running* — across three enums
(`turns.rs:3366-3372`). A test holds two of the three together;
the third is kept by hand (`turns.rs:3373-3374`).

## 5. What a caller can learn about the actor

| Question | Local | Remote | Class |
|---|---|---|---|
| Is it alive? | `is_running()` (`2333`) | infer from a call | **I** |
| Is a turn running now? | `is_busy()` (`2344`) | no | **I** |
| How deep is the queue? | `buffered()` (`2354`) | no | **I** |
| Did it end, and why? | `ended() -> Ended` (`2378`) | `NoSuchActor` only | **D** (`reply.rs:177`) |
| Did it restart? | `Undelivered::Restarting`, no reason | `"restarting: {reason}"`, with reason | **I** (`turns.rs:3207`) |
| Does this actor exist? | `System::contains` (`registry.rs:1711`) | `NoSuchActor` on a call | **I** |
| How many actors are mounted? | `System::len` (`1717`), `System::status` (`1768`) | no | **I** |
| What is in its state? | `with_state` (`2275`) | no | **E** |
| Is my key already used? | no | `key_state()` (`2669`, `2488`) | **D** |
| Is the other party gone? | no | `watch()` (`2684`, `2498`) | **E** |
| Was I authorized? | no question to ask | `Unauthorized` (`reply.rs:61`) | **E** |

`NoSuchActor` deliberately refuses one distinction that is available locally.
`reply.rs:79-81`: *"Deliberately does NOT distinguish 'never existed' from 'was
stopped'. The caller's next action is the same either way, and telling them
apart would leak that an id was once real."* `System::contains` answers the
first question locally with no such concern.

| N6 | Four vocabularies for departure | `Undelivered::Gone` (actor ended), `RemoteError::NoSuchActor` (id not mounted), `Departure` (connection ended), `Ended` (why the actor stopped) | `turns.rs:3192`; `reply.rs:98`; `watch.rs:13-16`; `observe.rs:452` |

N11 and N12 are one finding on the remote side that has no local twin.
`Undelivered` and `NotQueued` are **exhaustive** enums, so a local caller's
`match` is checked by the compiler (`turns.rs:3162-3165`, `3345-3351`). A peer
matching `Failed` matches a `String` with `starts_with`. The crate holds the
prefixes disjoint with a test
(`turns::tests::no_failure_prefix_is_a_prefix_of_another`, named at `reply.rs:130`,
defined at `turns.rs:4855`)
and states plainly that a `Failed` from a caller's own `Middleware` is outside
every guard (`reply.rs:145-147`).

## 7. The four that matter most

### 7.1 The error split is the only divergence the crate argues for, and it is right

RFC-04 §5.5 is a one-directional argument. It says a remote caller has failures
a local caller cannot have. That is true and it is physics. Every item in §4.3's
first list is a fact about a wire.

The argument does **not** cover the other direction, and the other direction is
where the real asymmetry sits. A local caller learns six endings, an observer's
error, liveness, busy-ness and queue depth. A peer learns one `NoSuchActor` and
five strings. Nothing in §5.5 defends that. The defence that exists is local, in
`reply.rs:177-180`, and it is an observation rather than an argument: *"A peer
has no `ended` to fall back on, so this prefix is the whole of what it learns.
Before it existed, a peer read `REFUSED` for both — the worst-informed audience,
given the same false word."*

So the seam has two distinct error asymmetries. One is defended and essential.
The other is undefended, and its shape is that **the remote caller is
systematically the worse-informed party** — except on the restart reason, where
it is better informed.

### 7.2 The restart reason inverts the whole pattern, and one trait choice causes it

Everywhere else the local caller knows more. On a restart the peer gets
`"restarting: {reason}"` (`turns.rs:4618`) and the local caller gets a unit
variant (`turns.rs:3215`).

The cause is written down at `turns.rs:3207-3213`: `Undelivered` derives `Copy`
and `Eq`, `TurnLost::Restarting` carries an `Arc<Ended>`, and an `Arc` is
neither. The fact crosses, the reason does not. The same paragraph closes the
escape: *"there is no other local door to the reason: `ended` does not resolve
on a restart, because a restart is not an ending."*

This is INCIDENTAL. Nothing physical prevents it. Two derive attributes and a
public escape hatch decide it, and `LocalActor::ask_catching` already answers
the richer type (`turns.rs:3941`) without being reachable from the generated
`Handle`.

### 7.3 `send` and `recv` are the cleanest ESSENTIAL pair in the crate

They are absent locally, absent from the blocking client, and present on both
remote surfaces. The argument at `macros.rs:3934-3953` names the physical object
rather than the inconvenience:

> A `send` handler is DEFINED by the `BodyReader` it reads, and a
> `BodyReader` reads a QUIC `RecvStream`: `body.rs` builds one from a
> `FrameReader`, which holds that stream by value. A `recv` handler returns
> a `Body`, which `body.rs` calls "a *value*, not a stream handle: a handler
> returns one and keylink drains it" — into a `SendStream`. Neither half
> exists in this process.

It then prices both closures — buffer a 4 GiB upload, or generalize
`FrameReader` over `AsyncRead` — and closes with the sentence that makes the
class unambiguous: *"Streaming is a transport capability, and this handle names
no transport."*

`blob` is the same fact at one remove. Local returns `BlobId`, remote returns
`BlobHandle`, and the difference is that a handle names a holder
(`macros.rs:3911-3915`).

### 7.4 `Middleware` and authorization are not local-versus-remote at all

The table above puts them in the remote column, and that is the observable
behaviour. The mechanism says something narrower. A layer wraps a `Dispatch`
(`rpc.rs:1390`). A `Dispatch` exists only when `Handle::service` builds one
(`macros.rs:2147`). Local methods call `ask` and never construct one
(`macros.rs:3853`).

So the real boundary is **served versus not served**, not remote versus local.
The consequence is visible on one actor: `Handle::service` says *"The local
`Handle` keeps working while this is served, and messages from both sides share
the one mailbox"* (`macros.rs:2035-2036`). Two callers reach one mailbox. One
passes through every layer, the authorization check and the idempotency ledger.
The other passes through none of them, and the actor cannot tell which is which
beyond `Caller::Local` versus `Caller::Peer` (`middleware.rs:389-397`).

`Caller`'s own doc states the half that is essential: *"There is no peer, no
handshake and no proven key, so there is nothing to attribute it to — and
pretending otherwise is the failure this variant exists to make impossible"*
(`middleware.rs:391-394`). That defends the **authorization** gap. It does not
defend the `Timeout`, `QueueTimeout` or logging gap, and `Undelivered::Expired`
already exists as the local name for a condition no local door can reach
(`turns.rs:3265-3267`).
