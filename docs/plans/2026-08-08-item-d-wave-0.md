# Item D — Wave 0 verdict: PROCEED, AMENDED

Date: 2026-08-08. Reviewed against `main@0ab8366`.

## The verdict

**D is right and the shape in the goal is wrong. Rename the module. Do not split
it. Delete the line-count criterion.**

## The refused design, recorded so a later author does not re-derive it

*Split `keylink/src/local.rs` into `runtime/` plus five or more siblings, under a
2,500-line-per-file ceiling.*

Three measurements refuse it.

### 1. The name `runtime` is already taken, by a different concept

`keylink/src/blocking.rs:48` documents its field as "The tokio runtime that
drives blocking calls", and `:55` declares `inner: Option<tokio::runtime::Runtime>`.
Measured with `rg -c runtime`: **64 lines in `blocking.rs`, 22 in `macros.rs`, 13
in `actor/registry.rs`**. One word would carry two meanings in one crate, and a
reader grepping `runtime` would get the actor loop and the thread pool together.

The collision is already visible in D's own success criterion. See point 3.

### 2. The 5,108-line premise measures documentation, not complexity

`local.rs` is **5,108 lines, of which 3,077 are comment lines** — measured twice,
by two agents, with agreeing figures. That leaves 1,812 code lines and 219 blank.
**The file is 35% code, and 35% is this crate's median**: `actor/registry.rs` 37%,
`idempotency.rs` 35%, `actor/remote.rs` 35%, `middleware.rs` 34%, `console.rs`
33%, `call.rs` 29%.

By code lines `local.rs` (1,812) sits beside `macros.rs` (1,779), which nothing
proposes splitting. **5,108 measures how much this repository documents, not how
much this module does.**

### 3. Two of D's three success criteria cannot grade D

- `rg 'Turn::run|\.run\(' keylink/src` is specified to "return exactly one" site.
  Run verbatim it returns **14 lines across 3 files**: 6 in `macros.rs`, 7 in
  `blocking.rs`, 1 in `local.rs`. Only `local.rs`'s `Box::pin((*turn).run(state,
  hooks))` is a turn dispatch. The other 13 are `runtime.run(..)` on the blocking
  runtime — the same name collision as point 1. A wave running this criterion
  reads 14 and cannot tell a regression from the baseline.
- "No file in the split exceeds 2,500 lines" gates nothing. Every natural region
  is already far below it: the test module is 1,351 lines, the local handle
  1,044, the turn 907, supervision 737. The ceiling forces at least three files
  only because 5,108 > 5,000, and **an arbitrary cut at 1,703/1,703/1,702
  satisfies it while being worse than the file it replaces.** A criterion that
  passes a bad split and fails no good one is not a criterion.

### What the split would have cost

- **14 visibility widenings.** `LOCAL_MAILBOX_DEPTH`, `observed_turn`, `Read`,
  `Message`, `Inbox`, `Watched`, `Keyed`, `dispatch`, `run_loop`, `Floor`,
  `Budget`, `retryable`, `Lent`, `supervise` each cross a proposed boundary.
  `pub(super)` bounds the widening to the subtree, so it never reaches the crate.
- **A falsified design sentence.** `local.rs:49` reads "its mailbox through a
  private `Inbox` trait". The word *private* is the design's own guarantee. The
  split makes it false, and the only fix is to weaken it — which the goal
  forbids at line 352.
- **A carved 176-line header.** The module header is one `//!` run whose sections
  cross every proposed group. Carving one continuous argument into five is a
  rewrite of the crate's densest design prose, not a move.
- **80 intra-doc link occurrences** crossing a new file boundary. Each must be
  fixed by a `use` import and never by a path-qualified link, because
  `[tasks.docs]` denies `rustdoc::redundant_explicit_links`.

## What D actually buys, and it is real

**The file name asserts something false.** `local.rs` declares `pub async fn
run_keyed` and `pub async fn run_keyed_supervised`, both re-exported from
`lib.rs`. Both are the keyed path. A reader looking for the keyed loop does not
look in a file called `local`.

A rename buys that truthful name for one `git mv` and about 25 line edits. The
split buys the same name and pays the four costs above for it.

## The amended shape

1. `git mv keylink/src/local.rs keylink/src/turn.rs`. **Not `runtime`.** No file
   of that name exists today — verified.
2. `lib.rs:212` `mod local;` → `mod turn;`. `lib.rs:316` repoints. **No name
   inside the braces changes**, so no public path moves.
3. `actor/remote.rs:60` and `actor/registry.rs:67` repoint their `use
   crate::local::` lines.
4. `.mise/tasks/anchors` rows D1, D2 and D3 repoint their target path. **The
   literals do not change, so `mise run anchors` proves the move.**
5. `scripts/replay-fate-breaks.sh` repoints 16 path arguments. No gate runs this
   script, so run it by hand and print the result.
6. `reply.rs:130` and `tests/supervision.rs:1306` repoint two prose mentions.
7. Rewrite only the header's first line so it describes both paths. Leave the
   other 175 alone.
8. Delete the 2,500-line criterion. Fix the `rg` criterion to name the dispatch
   site.

### Amended success criteria

`git diff --stat` shows one rename and under 30 changed lines. `rg -n
'crate::local|src/local\.rs' .` returns zero. `mise run anchors`, `mise run docs`
and `mise run gate` green. The `actor_memory.rs` slope reported and unchanged.

## Two hazards cleared by measurement, not by argument

**The memory slope is not a hazard for a move.** Two programs with byte-identical
async bodies were compiled, one with `dispatch` and `run_loop` in a single module
and one with `dispatch` moved to a sibling and widened. At `-C opt-level=0` and
`-C opt-level=2` both print `run_loop future size = 1136` and `dispatch future
size = 24`. Generator layout comes from a MIR transform that runs before
codegen-unit partitioning, so module placement cannot reach it. **Keep the slope
criterion anyway** — it guards the edits, not the move.

**`RECORD_BLOCKS` does not move on a rename.** The walk globs
`keylink/**/*.rs` and is path-insensitive. `local.rs` holds 8 of the harness
blocks, and a move redistributes them without changing the total. It *does* move
if header prose naming `break-once.sh` is copied into more than one new file —
which is another cost the split carried and the rename does not.

## The trap that governs sequencing

**`.mise/tasks/anchors` contains no `try` anywhere.** Its target cache does
`(ROOT / target).read_text()`. When `keylink/src/local.rs` stops existing, that
raises `FileNotFoundError` and the task dies with a traceback **before printing a
single check**. `anchors` runs in `pre-commit`, so **the commit that renames the
file cannot be created until rows D1, D2 and D3 are repointed in the same
commit.**

This is worth fixing beyond D: a gate that crashes on a missing target reports
nothing at all, which is strictly worse than reporting a failure.

## Ordering

**Land `compose-group` first, then D.** Both touch `keylink/src/lib.rs`. Under the
amended shape D is a `git mv` plus ~25 edits, so the ordering no longer carries
real risk either way — but the branch that is nearly finished should not rebase
for the one that has not started.

The goal's own reason for D-first — "so C, B and A land in the new files instead
of moving twice" — does not survive. None of C, B or A names `local.rs` as its
main edit surface; B edits prose at two `local.rs` lines. "Moving twice" is worth
two prose edits, not a reordering rule.

## What would change this verdict

If a later wave measures that `local.rs` blocks three or more concurrent branches
by merge conflict, the split earns its cost — and the shape is **two files, not
five**: keep `run_loop`, `Inbox`, `Watched`, `Keyed`, `Lent`, `supervise`,
`Budget`, `Floor` and both `run_keyed*` together, and move only `LocalActor` and
`deliver_to_local` out. That boundary costs **4 widenings instead of 14**.
