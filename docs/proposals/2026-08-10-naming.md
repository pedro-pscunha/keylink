# Naming the caller surfaces

Written 2026-08-10 against `main` at `f0f7df6`. It answers a proposal to rename
five public types for symmetry, and it refuses most of that proposal on evidence.

Four opus reviewers read the tree independently: prior art and Rust convention,
necessity, call-site ergonomics, and an adversarial pass. All four reported, and
they disagreed in three places. Every such place appears below as a choice with
the evidence for each side, not as a settled ruling.

Every number is measured, and four were corrected during the review:

- The call-site figures for `at`, `keyed_service` and `Client` came from a
  six-file sample. The whole repository gives 131, 26 and 116, not 80, 12 and 31.
- The recoverable name budget is **15 words**, not 19. The four `__` identifiers
  already cost the user nothing — that is what the underscores bought.
- `System` **does** have a per-actor getter, `serving(&id) -> Option<Serving>`
  (`registry.rs:1827`). An early draft of this document said it had none.
- The blast-radius table in §7 reproduces exactly.


## Implementation status (2026-08-11)

The amended goal in `docs/goals/2026-08-10-naming.md` supersedes the pre-PR-#47
assumptions in this proposal. PR #48 implements the §5 outcomes with that goal's
corrections. The PR is open against `main`; these names are not on `main` until it
merges:

- the public keyed vocabulary is `Registry`, `RegistryBuilder`, `RegistryClient`,
  `registry_alpn`, `Registry::stop`, and `Mountable`;
- generated setup now uses `setup(..)` or `restarting(..)`, followed by builder
  options and an `.actor()` or `.mountable()` terminal;
- keyed serving hangs from `registry.service(..)` and `registry.serve(..)`;
- generated caller capabilities live on the six traits exported by
  `keylink::prelude`;
- `LocalRef`, `at_local`, `RegistryClient::at`, and `Registry::ended` remain, while
  the two redundant generated `id()` accessors are gone;
- the unkeyed/keyed delivery and serving seams use their literal names.

PR #48 does not include the §9 open questions. `Handle`, `Client`, `IdempotentClient`,
`ActorRef`, `Handler`, `Governed`, and `connect` retain their names. Historical
measurements and rejected alternatives below remain evidence for the decision,
not a description of the current public tree.

## 0. The rule this document applies

The crate owner set the test:

> local/remote and singleton/multi may differ in a name **only where the
> difference is actually necessary**.

Stated as something a reader can apply:

**A word earns its place when deleting it lets a user write code that compiles
and is wrong, or when two things would collide in one namespace. Every other
word is a cost.**

Sharpened, because the sharp form decides every row below:

> **An axis the compiler already catches does not have to appear in a name. An
> axis that fails silently does.**

And "local against remote" is not one axis. It is three, and only one of them is
silent:

| Axis | Decided by | How a user learns they got it wrong |
|---|---|---|
| **A. Reply mechanism** | `Unanswered`/`NotQueued` against `Error` | **compile error**, three ways over |
| **B. Governed or not** | `impl Governed` for `ActorRef`, `Client`, `IdempotentClient`, **not** `Handle` (`macros.rs:3557-3562`) | **silence** — `handle.note(1)` skips the `Allowlist` and every `Middleware` layer and reports nothing |
| **C. Addressed or not** | an `ActorId` in the signature | **compile error** |

**The proposal puts axis A into six type names and drops axis B entirely.** Axis
B is the only one worth a word, and nobody — the proposal, this document, or any
reviewer — has proposed one. That is the open question §9 carries.

Locality usually fails that test, because the **constructor** already fixes it
and the user writes the constructor first:

```rust
journal::actor(state)                     // cannot produce a remote value
journal::Client::connect(&node, peer)     // cannot produce a local one
```

Their argument lists have nothing in common. A user who has written either one
mostly cannot then name the wrong type, because a user mostly names no type at
all. Every generated type is written module-qualified at every site; the corpus
holds one `use` of a generated item, `use super::inventory::Actor;`
(`demo/src/main.rs:686`), and it imports a trait to bring its methods into scope.

Measured over `keylink/tests`, `keylink/examples`, `demo/src` and the `README.md`
fences, excluding comment lines:

| Type | Produced | Named in code |
|---|---|---|
| `ActorRef<'a>` | 131, all through `svc::at(..)` | **2**, both in `tests/api.rs`, whose job is to pin names |
| `Handle<A>` | 268 door calls produce a handle or a mount | **25** |

The two rows disagree, and the disagreement is the useful part. `ActorRef` is
effectively anonymous, so its name costs nothing and buys only recognition.
`Handle<A>` is named 25 times, mostly because `compose` is generic over a handle
— `Pool<H>`, `Names<H>`, `Factory<H, K>` — so the crate already carries `H` for
"handle" as its own conceptual letter.

## 2. Ruling

**The verb table must be deleted. Four of the five renames must not ship. The
diagnosis behind the fifth is correct and its cure is a different word.**

**And the largest improvement here is not a rename.** Moving keylink's own verbs
onto traits returns 14 of the 15 words it steals from the user's own RPC
namespace, rewrites zero expressions, and uses a hatch the crate already opened
twice — §5.7. Read that section first if you read only one.

| Proposed | Ruling | Reason |
|---|---|---|
| `Handle<A>` → `LocalActorHandle<A>` | REFUSE | `Local` repeats the constructor. `Handle` against `Ref` already carries the real difference — see §4.1. |
| `Client` → `RemoteServiceHandle` | REFUSE | Most-typed name in the crate; `Handle` is false for a type whose terminator is `close()` on a connection. |
| `KeyedClient` → `RemoteActorSystem` | REFUSE | Names a connection a "system" and promises `mount`, `stop` and `abort` that a ruling of the same date forbids on any peer surface. |
| `ActorRef` → `RemoteActorRef` | OPTIONAL | Correct against prior art. It buys recognition, not disambiguation. See §4.1. |
| `System` → `LocalActorSystem` | REFUSE the name, ACCEPT the diagnosis | `System` is the wrong word — it means *runtime* in actix and Akka. `Local` is not the repair, and it labels the type with the one property it lacks. **The replacement is `Registry`, ruled 2026-08-10.** See §4.2 and §5.1. |
| new `LocalActorRef` | REFUSE | Largely shipped already, as `compose::Names`. See §3.1. |

## 3. Four findings that decide it

### 3.1 The local half is two populations, and the one the proposal means cannot exist

The proposal assumes a gap: a local twin of `at(&client, id)`. keylink has
**three** id-keyed registries, and the proposal names one.

| Type | File | Key | Holds | Members reachable |
|---|---|---|---|---|
| `System<M>` | `actor/registry.rs:1480-1884` | `ActorId` | `Mounted<M>` — the state type `A` is **erased** | only over the wire |
| `compose::Names<H>` | `compose/names.rs:106-224` | `ActorId` | `H` — the handle stays **typed** | in process, directly |
| `Subscribers` | `subscribers.rs` | `EndpointId` | a parked reply | in process |

`Names` documents itself as *"Names for the actors in this process, unregistered
when they end"*, and `get(&name) -> Option<H>` (`names.rs:224`) already answers
`Option<journal::Handle<Journal>>` — typed, local and callable. That is what
`LocalActorRef` was for.

`names.rs:73-81` records that `Names` and `Subscribers` are *"one generic
registry waiting to be merged"*, filed in RFC-07 §8.

**State the limit precisely, because it decides the design.** The two registries
hold **different populations**. `Names::register(name, handle, ended)` files a
handle the caller already owns, so `Names` never reaches into a `System`. So:

- A local, typed, id-addressed **call** already ships — for actors you spawned
  with `svc::actor(..)` and registered yourself.
- What does not exist, and cannot exist without new machinery, is a callable
  local handle for an actor **mounted in a `System`**. `System<M>` is generic
  over the mailbox type and erases `A`, and `Mounted<M>` holds only a boxed
  closure (`registry.rs:355-360`). A lookup there can return only an
  `A`-erased value.

That erasure is ractor's documented `where_is -> ActorCell` hazard, and ractor
states the consequence in its `registry` module: the caller *"additionally
requires knowledge of the `crate::Actor` in order to send messages to it ... or
agents will runtime panic on message reception"*.

**Consequence.** The defect is not a missing type, and a symmetric `LocalActorRef`
would not be the type the proposal thinks it is. The defect is that the names do
not tell a user which of the two registries to reach for — and `System`, the one
whose name sounds like the answer, is the one that by construction **cannot**
hand back a callable local handle.

### 3.2 The verb table is not a rename

Measured against `actor/registry.rs`, `System<M>`'s complete inherent surface is
`builder`:1480, `mount`:1512, `shutdown`:1688, `abort`:1712, `contains`:1737,
`len`:1743, `is_empty`:1749, `status`:1794, `serving`:1827, `evict_idle`:1884.

| Proposed verb | Reality |
|---|---|
| `system.actor(id)` | Does not exist. `macros.rs:1377` makes the generated `System` a bare `pub type` alias to a foreign type, so an inherent impl is `error[E0116]`. |
| `system.mount(id, state)` | `mount` takes `Mounted<M>`, not a state. Taking a state needs a bound on the generated `Actor` trait, which keylink cannot reach — the reason is written at `macros.rs:1385-1392`. |
| `system.stop(id)` | The method is `shutdown(&id, budget: Duration) -> Option<Ended>`. The proposal drops a mandatory argument and changes the return type. |
| `system.ended(id)` | Does not exist. `ended` is a `Handle` method (`macros.rs:2737`). |
| `system.status(id)` | `status()` takes no id and returns `Vec<ActorStatus>`. The per-id reader already exists as `serving(&id) -> Option<Serving>` (`registry.rs:1827`), which the proposal never mentions. |
| `system.abort(id)` | Exists. |

One of six verbs survives contact.

### 3.3 The remote half of the verb table was refused today, in writing

`docs/plans/2026-08-10-peer-administration.md:175`:

> **Ruling: `shutdown`, `abort`, `evict_idle` and `mount` ship on no peer surface
> in this wave.**

Two measured reasons sit above it. `console.rs:26-27` places
`Allowlist::anyone()` one line above `Allowlist::only([operator])`, and that file
is what a new admin service gets copied from — so a copied wiring line hands a
remote kill switch to the world. And no deployed experience of an admin ALPN
exists, so the first release of the vehicle would also be the first release of
the weapon.

The proposal concedes this in its own text and asserts the verbs anyway.

### 3.4 The rename spends nothing, and the verbs it hides could spend a lot

`macros.rs:128-141` documents the mechanism: a declared `rpc` whose snake_case
form matches an inherent method on a caller surface is `error[E0592]`, there is
no reserved-word list, and the taken set is per surface.
`docs/plans/2026-08-10-peer-administration.md` §2.3 measured that set at `2dd3eb4`
and shipped two doctests rather than a reservation mechanism.

The union over the surfaces that **receive the per-rpc expansion** is 15 names:

- from `Handle<A>` — `service`, `serve`, `with_state`, `stop`, `abort`,
  `is_running`, `is_busy`, `buffered`, `ended`
- from `ActorRef<'_>` — `id`
- from `Client` — `connect`, `with_idempotency`, `key_state`, `watch`, `close`

Ten are single words a user can reach for by accident. `KeyedClient` spends
nothing, because its impl block (`macros.rs:2986-3074`) carries no per-rpc
expansion.

**Count it in two units, because both are true and they answer different
questions.** Nineteen *identifiers* are taken: these fifteen plus `__status`,
`__reserve`, `__try_reserve` and `__reserve_owned`. `macros.rs:169-175` measured
that the `__` names are **taken and not unreachable** — `pastey`'s `:snake`
reaches `__status` from a legal `__Status` — and calls the prefix *"a convention
and not a mechanism"*. So the escape does not delete a cost. It **moves** it from
a word a user wants, `status`, to one nobody wants.

**Fifteen is the number that matters, and it is the only one a remedy has to
return.** The four `__` identifiers are already free to the user, which is what
the underscores bought. Counting them among the recoverable names inflates any
remedy's win by four. Nineteen is the identifier count and it is a curiosity;
fifteen is the bill.

**Ruling on the proposal: budget-neutral at best, worse at worst, and
undecidable as written**, because it never says which type the verbs land on. On
a registry they cost nothing. On a `Ref` they cost real names, and `status(id)`
would spend back the one word the `__` escape moved out of the way.

**§5.7 returns 14 of the 15, and rewrites no expression.** That is a larger
user-facing win than every rename in this document put together.

## 4. The words themselves: one the proposal would break, one it correctly finds

### 4.1 `Handle` against `Ref` is already right, and the proposal would break it

| | `Handle<A>` | `ActorRef<'a>` |
|---|---|---|
| Ownership | owns; `Clone` at `macros.rs:2288`; dropping the last one ends the actor | borrows a `&'a KeyedClient`; owns nothing |
| Terminator | `stop`, `abort` — ends an **actor** | none |
| Errors | `Unanswered`, `NotQueued` — exhaustive enums | `Error` — `#[non_exhaustive]`, plus five `Failed` prefixes |

`Handle` against `Ref` is the Rust reading of exactly that difference. Putting
`Local` and `Remote` in front adds a second, weaker encoding of a distinction two
correct words already carry.

**One correction to the strong form of this ruling.** "Locality earns a word
nowhere" is wrong by one. The crate root carries exactly two names with the axis
word, and they split:

- **`RemoteError`** (`reply.rs:81`, re-exported `lib.rs:330`) **earns it.** It
  sits on the same import line as `Error`. Delete `Remote` and it collides.
- **`LocalActor`** (`turns.rs:3635`, `lib.rs:336`) **spends it for nothing.**
  No `RemoteActor` exists anywhere in the crate. Its real property is the one
  `macros.rs:2769-2771` names — it is keylink's own type and shares its namespace
  with nobody — and `Local` does not say that. Debt, not this wave.

Correct statement: **the locality axis earns a word in exactly one existing
name, and that name already has it.**

`RemoteActorRef` remains defensible on prior art alone: kameo 0.22.2 ships
`ActorRef<A>` and `RemoteActorRef<A>` for this exact pair, and no crate in the
sample ships `LocalActorRef`, `LocalActorHandle` or `LocalActorSystem`. **The
ecosystem marks the special case and leaves the default bare.** If one word ships
from the whole proposal, that is the word — and it must be the only one.

One caveat that is not a naming question: `ActorRef<'a>` borrows so that every
actor of a service on one node is reached over one connection with one
congestion-control state (`macros.rs:3085-3089`). Dropping the lifetime is a
design change, not a rename.

### 4.2 `System` means runtime everywhere else, and here it means a served map

- actix-rt 2.11 documents `System` as *"A manager for a per-thread distributed
  async runtime"*.
- Akka's `ActorSystem` holds the guardian actor and is the process entry point.
- Every ecosystem uses a different word for the id-to-actor map: ractor
  `registry` plus `where_is`, actix `Registry`, Erlang `register/2`, Akka
  Receptionist.
- keylink's own generated doc has to gloss the word to mean what it means:
  `macros.rs:1369-1377` reads *"A registry of **this service's** live actors"*.

A name that needs a gloss to say "registry" must be spelled `Registry`.
`LocalActorSystem` makes it worse, because `ActorSystem` is Akka's exact word for
the process-wide runtime, and keylink's is per-service, one per `service!` block.

`System` is also the most-named generated type — 18 type positions, of which 9
are load-bearing — so a better word pays more here than anywhere else.

## 5. What to ship

Each item stands alone and can ship on its own commit. They are ordered by
blast radius, smallest first — **not** by value. The highest-value item is §5.7,
which is last because it is the only one that is not a rename.

### 5.1 `System` → `Registry`, and `Keyed` leaves the public surface

**Settled by the owner on 2026-08-10: the word is `Registry`.** The argument that
produced it, and the alternative it beat, are kept at the end of this section as
the record of why — not as an open question.

| Today | Ship |
|---|---|
| `keylink::System<M>` | `keylink::Registry<M>` |
| `keylink::SystemBuilder<M>` | `keylink::RegistryBuilder<M>` |
| `svc::System` / `svc::SystemBuilder` | `svc::Registry` / `svc::RegistryBuilder` |
| `svc::KeyedClient` | `svc::RegistryClient` |
| `svc::keyed_alpn()` | `svc::registry_alpn()` |
| `svc::keyed_service(&system, allow)` | `registry.service(allow)` — see §5.3 |
| `svc::keyed_serve(&node, &system, allow)` | `registry.serve(&node, allow)` — see §5.3 |
| `System::shutdown(&id, budget)` | `Registry::stop(&id, budget)` |

`Registry` is local by the absence of a marker; `RegistryClient` is remote by its
head noun, which is the word tonic and tarpc both ship. The pair carries the
whole singleton-against-many distinction with **no locality word at all**, and
`Keyed` disappears exactly as the proposal wanted.

`stop` for `shutdown` closes audit defect N8 — three verbs for stopping, split by
side — and keeps the mandatory budget.

**The word was contested, and two reviewers split on it with evidence. The record
of the decision follows.**

*For `Registry`:* it is the ecosystem word for this exact thing — ractor's
`registry` module plus `where_is`, actix's `Registry`, Erlang's `register/2`.
keylink's own generated doc already glosses `System` as *"A registry of **this
service's** live actors"* (`macros.rs:1369-1377`).

*Against `Registry`:* it names the **genus**, and separating the genus is the
whole point. `compose::Names<H>` is a registry and `Subscribers` is a registry,
and `names.rs:73-80` records those two as *"one generic registry waiting to be
merged"*. A public `Registry` also needs the private `struct Registry<M>` at
`registry.rs:673` renamed first — 33 occurrences in that one private file, so
cheap but not free.

*The alternative is `Directory`*, with `DirectoryClient` and `directory_*`. It is
free as an identifier — `rg -nw Directory keylink/src demo/src` returns nothing,
and it collides with no `std` name and none of the four `iroh` re-exports at
`lib.rs:346`. It needs no prerequisite rename, and it does not claim the genus.

**Two measurements settle it.**

*For `Registry`: the crate already uses the word for this exact thing, in prose,
at scale.* Case-insensitive hits — `registry.rs` **103**, RFC-07 **72**, the
peer-administration plan **45**, RFC-04 **38**, `turns.rs` **36**, the remote
audit **26**. The module is `keylink::actor::registry`. §7 shows `docs/` is the
larger half of the blast radius, and this is the direction that makes it
**cheaper**: RFC sentences that already say "the registry" become literally true
instead of drifting further from the code.

*Against `Directory`: the word is taken in this repo, by its universal meaning,
in a crate a keylink user touches.* `keylink-persist/src/file.rs:1` reads *"The
local-file adapter. One directory, one file per state."* Also `:21`, `:23`,
`:75`, `:93`, `:250`, `:276`, plus `keylink/src/persist.rs:105` and eight in
`mise.toml`. Shipping `keylink::Directory` would put two meanings of one word in
one crate family, and the incumbent is the one every reader already holds.

*Ruled: `Registry`.* Its one hard cost is renaming a private type in one private
file — the cheapest item in this document. `Directory` trades that for a live
word collision in a sibling crate, abandons the vocabulary the RFCs already argue
in, and is nobody's word for this — which fails the same test that keeps
`Client`.

**So the prerequisite is now load-bearing.** `actor/registry.rs:673`'s private
`struct Registry<M>` must become `Shared<M>` in its own commit, before the public
type can take the name. 33 occurrences, one private file, no public surface.

*Honest residue, either way.* Neither word says the property that actually
distinguishes this type: it is the **served** set, and its members are the ones a
local caller cannot call. The four doc cross-reference lines below are what carry
that, whichever word wins.

*One more overload to know about.* `.mise/tasks/anchors` uses "registry" 35 times
for the break-record registry. Prose only, no identifier, and no bearing on the
public API — recorded so a reader who greps the repo is not surprised.

*And a third option that is not a cop-out:* **ship nothing here and add four doc
cross-reference lines** — on `System`, `compose::Names`, `svc::actor` and
`svc::spawn`, each naming the others and saying which one a caller can call in
process. That fixes the defect a user actually meets at four sites instead of 89.
The fork a user gets wrong is one call earlier than the type name, at
`svc::actor(state) -> Handle<A>` against `svc::spawn(state) -> Mounted`, and
**neither of those two names says what it forks on.**

**Whatever word wins, it must not claim the property this type lacks.** Of the
two id-keyed actor registries, `System` is the one whose members a local caller
**cannot** reach. That is why `LocalActorSystem` was the worst candidate of all:
it labels the type with the one thing it does not do.

### 5.2 `Mounted` → `Mountable`

`Mounted<M>` holds `run: Loop<M>` — *"One actor's loop, before it has a mailbox
to run against"* (`registry.rs:355-364`). Its own `#[must_use]` reads *"an
unmounted actor is dropped"*. The type is named for the state it is not in. Two
sites name it.

### 5.3 Free functions become methods

A free function inside a generated module is invisible to `.` completion, so it
is where an agent invents a name.

| Today | Calls in repo | Ship |
|---|---|---|
| `at(&client, id)` | 131 | `client.at(id)` |
| `keyed_service(&system, allow)` | 26 | `registry.service(allow)` |
| `keyed_serve(&node, &system, allow)` | 1 | `registry.serve(&node, allow)` |

Counted over `keylink/tests`, `keylink/examples`, `demo/src` and the `README.md`
fences with `rg "\b[a-z_]+::at\("` and its two siblings, comment lines removed.
`tests/actors.rs` alone holds 80 of the 131.

`Handle` already carries `.service(allow)` and `.serve(node, allow)`
(`macros.rs:2452`, `:2570`), so this makes the local singleton and the local
registry answer the same two verbs. `service(handler, allow)` and
`serve(node, handler, allow)` stay free functions: the handler is the argument,
so there is no value to hang them on.

### 5.4 Nine spawn doors become four

Measured across the test suite, the examples, `demo/src` and the README fences:

| Door | Calls | Door | Calls |
|---|---|---|---|
| `spawn` | 105 | `spawn_wired` | 8 |
| `actor` | 81 | `actor_deep` | 4 |
| `actor_with` | 38 | `spawn_supervised` | 2 |
| `supervised` | 19 | `supervised_deep` | 1 |
| `actor_wired` | 10 | **total** | **268** |

Two doors carry 186 of 268 calls, which is 69 percent. Nine names encode three
independent things and the encoding is incomplete — the keyed row has no `_with`
and no `_deep` member, so the grid already has holes.

```rust
pub fn actor<A: Actor>(state: A) -> Handle<A>;   // 82 sites, unchanged
pub fn spawn<A: Actor>(state: A) -> Mountable;   // 104 sites, unchanged
pub fn setup<A: Actor>(state: A) -> Setup<A>;    // everything else
pub fn restarting<A: Actor, N, Fut, F>(factory: N, limit: Intensity) -> Setup<A>;
```

`Setup<A>` carries `observe`, `feeds` and `backpressure`, and two terminals
choose the target:

```rust
let ledger    = ledger::setup(state).observe(saver).actor();
let warehouse = inventory::setup(Warehouse::seeded()).backpressure(park(32)).actor();
registry.mount(id, journal::setup(Journal::default()).feeds(feeds).mountable())?;
```

The empty `vec![]` leaves the four-argument doors, the grid holes close — a keyed
actor can take observers and a backpressure policy for the first time — a fifth
option costs a method rather than two doors, and 69 percent of existing sites do
not change one character.

`restarting` is a separate door because its first argument is a factory rather
than a state. That is a different kind of thing, so it is not an option on a
builder.

### 5.5 Two stale sentences, independent of any rename

- `macros.rs:134-135` teaches the per-surface rule with *"`at` is free on a
  `Handle` and taken on a keyed client"*. `rg -n 'fn at\b' keylink/src/macros.rs`
  returns one hit, the free function at `:3091`. `KeyedClient` has no `at`
  method. The `ended` half of that sentence is still true.
- `docs/plans/2026-08-10-peer-administration.md:203` carries the same stale row.

Two documents drifted from one refactor, and one of them is the document that
teaches the rule.

### 5.6 `singleton` leaves the public names, and the honest word is `unkeyed`

The crate already wrote this finding against itself, at `macros.rs:2375-2396`:

> The word **singleton** appears elsewhere in these docs, and it names **two
> different things**. One gloss cannot cover both. … Where it names an **actor**
> … read *"a local actor"*. … Where it names an **ALPN, a contract or a
> `Client`** … read *"unkeyed"*.

The same block closes the escape route: *"the free `service` takes a plain
`Handler` with **no actor anywhere** and registers on the same `alpn()` this
method does."* So **"the one instance behind an unkeyed ALPN" describes something
that need not exist** — `svc::service(handler)` (`macros.rs:840`) puts a
stateless `Handler` there, with no state, no mailbox and no instance. Any name
built on "one instance" is false for that case.

`unkeyed` is exact, it is about addressing, and the crate already uses it — 18
occurrences in `keylink/src` against 66 for `singleton`.

Two public names carry the wrong word, and their twins make the pair read as
"singleton against actor" when both deliver to an actor:

| Today | Ship |
|---|---|

### 5.7 Recover the name budget with traits, at zero call-site cost

This is the largest single improvement available, and the proposal does not
reach for it. It is not a rename at all.

**The mechanism.** Two inherent methods of one name in one `impl` block are
`E0592`. An inherent method **plus a trait method** of the same name are legal
Rust, and the inherent one wins method resolution. So every keylink verb that
moves from an inherent `impl` to a trait stops spending a word, and the user's
own `rpc` of that name simply shadows it.

**The crate already does this, twice, and did not notice it was a hatch.**

- `keylink::Dial` (`peer.rs:38`) carries `dial`, implemented for `Client`
  (`macros.rs:3185`) and `KeyedClient` (`:3076`). No surface has an inherent
  `dial`, so `dial` costs zero budget today, and `Peer<orders::Client>` still
  works generically.
- `Calls` (`macros.rs:3491`) is a **generated trait** carrying the user's own
  rpc method names, implemented for all four surfaces at `:3504`, `:3516`,
  `:3528` and `:3540`. Trait-carried methods on caller surfaces are half the
  existing design.

**The shape.**

| Trait | Implemented for | Carries |
|---|---|---|
| `keylink::Wire` | `Client`, `RegistryClient`, `IdempotentClient`, both `blocking::` twins | `close`, `watch`, `key_state`, `with_idempotency`, `status` |
| `keylink::Own` | `Handle<A>` | `stop`, `abort`, `ended`, `is_running`, `is_busy`, `buffered`, `with_state`, `status`, `reserve`, `try_reserve`, `reserve_owned` |
| `keylink::Servable` | `Handle<A>`, `Registry` | `service`, `serve` |
| inherent, kept | `Client`, `RegistryClient` | `connect` |

**What it costs and what it returns.** Roughly 465 call sites across 26 of 32
files use the fifteen words. The trait remedy rewrites **zero expressions** and
adds one `use keylink::prelude::*;` to each of those 26 files — 26 new lines
against 465 rewritten under a free-function remedy, and a free function is also
invisible to `.` completion. No prelude exists today
(`rg 'pub mod prelude' keylink/src` returns nothing), so the prelude ships in the
same wave or the remedy does not land.

**Count the return honestly: 14 words, not 18.** The recoverable pool is the
**fifteen** plain names. The four `__` identifiers are already free to the user —
that is what the underscores bought, argued at `macros.rs:2756-2771`: *"a bare
`reserve` here is a `duplicate definitions` error for any service declaring an
rpc called `Reserve` — which is the rpc this crate's own README, RFC-04 and
`demo` all use as their example."* Counting them as recovered inflates the win.
Keeping `connect` inherent spends one more. **So: 14 words returned, and the `__`
convention retires with them** — a readability gain, not a name gain.

**`connect` is the one word worth keeping inherent.** It is the most-typed door
at 115 sites, and `Client::connect` is the shape an agent produces unprompted. A
trait cannot rescue it cleanly: as an associated function it is reached by path,
so a user's `rpc Connect` still breaks `Client::connect(&node, addr)` at the call
site even though the definitions no longer collide. A user who needs
`rpc Connect` meets a clear `E0592` naming the word and renames in one edit.

**Delete two of the fifteen instead of moving them.** `.is_busy(` and
`.buffered(` have **zero** call sites in the whole corpus, measured. `Serving
{ busy, queued }` (`observe.rs:774`) already carries both facts, `Handle::__status`
returns it (`macros.rs:2713`), and `System::serving(id)` returns the same type
from the other side (`registry.rs:1827`). Two words recovered before any trait
exists.

**The unpriced cost: the refusal goes from loud to silent.** `error[E0592]` fires
today at the `service!` declaration and names the exact word. A trait method is
not an inherent method, so that refusal disappears — and inherent resolution
wins, so a user's `rpc Stop()` silently takes `handle.stop()` and keylink's verb
survives only as `Own::stop(&handle)`.

**This is not hypothetical. The crate already ships two live instances of it.**
`impl compose::Reserving for Handle<A>` (`macros.rs:2922-2934`) gives `Handle`
the trait methods `reserve` and `status`, and `macros.rs:194-196` records the
measured control that *"`rpc Status()` in this position COMPILES."* So a user's
`rpc Status()` already shadows `Reserving::status` today, with no diagnostic.

It is still the right trade — a user winning a name they declared beats being
refused — but say so in the docs, and keep trait-carried verbs out of any doc
example that calls them unqualified.

**Result: 15 words spent today, 1 after.** All eight of these are `E0592`
now and compile after:

```rust
rpc Close(id: u64) -> ();      rpc Abort(id: u64)  -> ();
rpc Stop(id: u64)  -> ();      rpc Ended(id: u64)  -> bool;
rpc Watch(id: u64) -> Feed;    rpc Status()        -> Health;
rpc Id()           -> u64;     rpc Service(n: String) -> Svc;
```

**A rule falls out of it.** `ActorRef` — and any local twin — should carry **no
inherent method at all**. Today it spends `id` and `__status` on a type that is
named twice and produced 131 times. Move `id` to a trait or drop it, because
`at(id)` was handed the id by its own caller.

**And the same rule redeems the proposal's verb table, in one place.** `Registry`
is not a caller surface and carries no rpc method, so `registry.stop(id)`,
`registry.abort(id)` and `registry.at(id)` cost the user nothing. The uniform
verbs are right **on the local registry and only there**. They stay wrong on the
remote client, for §3.3's reason.

**Four residual costs, stated rather than hidden.**

1. The trait must be in scope. A missing import is `E0599`, which names the trait
   to import, so a reader or an agent recovers in one step.
2. A user who declares `rpc Close` shadows `Wire::close`. Their name wins, which
   is what they asked for, and keylink's stays reachable as
   `keylink::Wire::close(&client)`. Today the same declaration refuses to compile
   the whole service, so this is strictly better.
3. A bound `C: Calls + Wire` calling `c.close()` where the user also declared
   `rpc Close` is `E0034`. UFCS fixes it, and it needs both conditions at once.
4. rustdoc demotes these methods from "Implementations" to "Trait
   Implementations", which sits lower on the page. That is the real price.

**One defect found on the way.** `Dial::dial` forwards to `Self::connect`
(`macros.rs:3190`). One operation carries two verbs, one on a trait and one
inherent. Pick one when the traits land.

## 6. What must not ship

- **The remote verb table.** Refused by a ruling of the same date (§3.3).
- **`LocalActorRef` on a rename commit.** It is a new feature. It needs a `Calls`
  implementation, a decision about the error type for an id that is not mounted,
  and its own tests. `compose::Names` may make it unnecessary (§3.1).
- **`status(id)` as written.** It changes a shipped signature and duplicates
  `serving(&id)` (`registry.rs:1827`), which the proposal never mentions. Under

  budget — it is that the method already exists under another name. Rename
  `serving` or keep it. Do not add a third spelling.
- **`Client` → anything.** 116 code occurrences — 87 of them exactly
  `svc::Client::connect(..)`, plus 29 in type position — which makes it the
  most-typed generated word in the crate by a wide margin. It is
  also the strongest prior a human or an agent holds: tonic generates
  `GreeterClient`, tarpc generates `WorldClient`. An agent that half-remembers
  this API types `inventory::Client::connect`. Under the proposal that stops
  compiling, and rustc offers no similar-name help, because `Client` and
  `RemoteServiceHandle` share no substring.

## 9. Open, and for the owner to rule

**Ship the traits, or keep the inherent methods?** §5.7 returns 14 of the 15
words and costs a prelude, one import in each of 26 files, a demotion in rustdoc,
and the loud-to-silent change in how a name clash is reported.
It is the one item here that changes how the API is *reached* rather than what it
is *called*, so it deserves a separate decision from every rename above.

**`connect` against `dial`.** `Dial::dial` forwards to `Self::connect`
(`macros.rs:3190`). One operation, two verbs. If the traits land, this is the
moment to pick one.

**The axis nobody has named.** §0 records that `Governed` is the one axis that
fails **silently**: `handle.note(1)` skips the `Allowlist` and every `Middleware`
layer and reports nothing, and no name anywhere says so. By this document's own
rule that is the only axis that has earned a word, and neither the proposal nor
any reviewer proposed one. It is the most valuable naming question left open.

**`with_idempotency` is a type on one side and a field on the other.**
`Client::with_idempotency` returns `IdempotentClient` (`macros.rs:3240`).
`KeyedClient::with_idempotency` returns `Self` (`macros.rs:3014-3017`), setting an
`Option<Idempotency>` field. One capability, two shapes, and no rename in the
proposal touches it. It is a larger inconsistency than any name the proposal does
address.

**Two more audit entries have gone stale**, beyond the two §5.5 names. seam.md N5
is already fixed — `deliver_to_local` no longer exists. seam.md N2 is stale too:
`Unanswered` has three variants, and the seven it describes moved to `Withheld`
(`observe.rs:997`). Anyone rebuilding an argument from that audit must re-measure
first.

**`Handler` beside `Actor`.** In actix and xtra a single type implements `Actor`
**and** `Handler<M>` together. In keylink they are mutually exclusive
alternatives — `&self` stateless against `&mut self` stateful. That is the
highest-cost misreading in the crate for an agent, because the prior is strong
and wrong. Prior art still recommends keeping both names, because they match
keylink's own two doors, `service(handler, allow)` and `spawn(state)`, and
correcting the doc costs one sentence on each trait. A rename here buys
consistency with an outside crate at the cost of consistency with the crate's own
free functions.

### 10.2 Gap 1, and it is a precondition — **55 `compile_fail` guards and no `trybuild`**

`git ls-files 'keylink/src/*' | xargs rg -c compile_fail` counts **55 fences
across 10 files**: `macros.rs`, `turns.rs`, `representability.rs`,
`compose/factory.rs`, `compose/group.rs`, `actor/registry.rs`, `actor/remote.rs`,

Chapter 7 closes on exactly this: *"Without the compile-fail test, 'it is
impossible now' is an unverified claim, and it is the one that silently rots."*
Its remedy is `trybuild::TestCases::new().compile_fail("tests/compile_fail/*.rs")`,
which compares against a checked-in `.stderr` and therefore pins **why** the
compilation failed.

**A rename is the single change most likely to satisfy a `compile_fail` for the
wrong reason.** An unknown name is a compile error, so the fence goes green while
proving nothing. §8 flags one instance, `lib.rs:292`. The real exposure is 55.

The crate already knows the hazard and answers it by hand — `macros.rs:139-145`
records that *"rustdoc does not check the code after `compile_fail`, so an
annotated code asserts a verification it does not perform — this project has
shipped five guards that were satisfiable without proving their claim"*, and the
convention is to measure the error codes and write them in a comment beside the
fence. That is a convention, and the handbook's point is that a convention is not
a mechanism.

**Ruling: before the rename lands, either port the guards that mention a renamed
type to `trybuild`, or re-measure each one and record the error code it actually
produces after the rename.** Doing neither converts a real guard into a
tautology, 55 times over, in one sweep.
